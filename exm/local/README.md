# Local CWT and IHLE example

Run `sh prepare.sh`, then `sh serve.sh`. In another terminal run `sh check.sh`.
The result includes `SIGNED-TRUSTED` and the protected asset `example.test`.
The authority key is explicitly trusted; its endorsement authorizes the emblem key for purpose 1. Neither token includes an organization identifier, so no CT commitment or
external network access is needed. Keys and short-lived tokens are generated in
`tmp/` and can be regenerated by rerunning `prepare.sh`.

`probe -qtype A` receives the tokens in Additional. Change the query to
`-qtype IHLE` to receive them in Answer. The server supports UDP and TCP; `probe`
automatically retries truncated responses over TCP. The default experimental
IHLE number is private-use TYPE65400; both commands accept `-ihle-type`.

`.cwt` files contain one hexadecimal signed CWT per line. `.hex` record files
can also contain public COSE_Key maps, one per line. Output uses uppercase hex;
input is case-insensitive and permits whitespace within the hexadecimal text.
Wire records contain the decoded CBOR bytes. `records` also accepts `.cbor`
files containing one binary CWT or COSE_Key.

`records -pk-alg ES256 public.pem` emits a bare public COSE_Key without requiring
a signing key. It omits `kid`; readers ignore any supplied key `kid` and compute
the identifier themselves. Discovered keys provide verification material only; `-trusted-pk` supplies local trust. Key CWT containers from the earlier prototype
are no longer used.

Omitting `-trusted-pk` and `-trusted-pk-alg` from `check.sh` gives
`SIGNED-UNTRUSTED`: both verification keys are present in the records, but
neither is explicitly trusted.
